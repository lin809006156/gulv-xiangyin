# 卦象心音 · 交付文档

> 观身边之物起卦，为每一卦生成一段心音。  
> 传统文化与艺术创作，不含任何预测功效。

本项目交付**三个可运行形态**，共用同一套核心逻辑：

| 形态      | 目录              | 状态                | 适合场景         |
| ------- | --------------- | ----------------- | ------------ |
| PWA 网页版 | `web/`          | 可安装到桌面、离线可用       | **当前开发重心（APP 载体）** |
| 手机 APP  | Capacitor 配置已就绪 | 一条命令打出 APK / IPA  | 应用商店上架       |
| 微信小程序   | `miniprogram/`  | 完整工程，可直接导入微信开发者工具 | 暂缓维护，随时可恢复 |

> 2026-10 起开发重心转向 APP（以 PWA 网页版为载体，Capacitor 套壳上架），
> 界面已重构为「起卦 / 音乐 / 学易」三栏 + iPhone 玻璃拟态风格，详见「三＋」节。

```

                      │
      ┌───────────────┼───────────────┐
      │               │               │
```

## 〇、文献依据：每一条定义都可查证

本项目的核心原则是**凡定义必注出处**。所有卦象取象、乐器归属、五音清浊、物象映射，
都集中在 `core/classics.js` 一个文件里，且按三档标注来源等级：

| 标注         | 含义                     | 当前条目数 |
| ------------ | ---------------------- | ------- |
| **典籍原文**   | 见于先秦两汉传世典籍，可直接查证原句     | 64     |
| **后世类书**   | 见于宋元以来类书与民间口诀        | 72     |
| **当代类推**   | 古籍未载，依《说卦传》卦性原理推演（必写推演理由） | 67     |

界面上的「文献依据」面板会把这些出处逐条摊开，并显示取舍理由与异说。

### 关键依据

- **卦象与卦德** ——《周易·说卦传》「乾，健也」「坤，顺也」及八卦物象原文
- **物象归属** ——《梅花易数·象数易理篇》八卦万物属类表，并参民间类象歌诀
- **卦 → 乐器** ——《白虎通·礼乐》引《乐记》「埙，坎音也；管，艮音也；鼓，震音也；
  弦，离音也；钟，兑音也；柷敔，乾音也」；清人陈立《白虎通疏证》补「箫当为巽音，磬当为坤音」
- **八音材质** ——《白虎通·礼乐》「土曰埙，竹曰管，皮曰鼓，匏曰笙，丝曰弦，石曰磬，金曰钟，木曰柷敔」
- **五音清浊** ——《礼记·乐记》郑玄注、孔颖达疏「宫属土，其声至浊……商属金而声次浊……
  角属木而其声清浊相半……徵属火，乃声之次清者……羽属水，乃声之最清者」
- **五音名义** ——《白虎通·礼乐》「角者跃也，徵者止也，商者张也，羽者纡也，宫者容也」
- **五脏配属** ——《素问·金匮真言论》五脏配五音
- **起卦法** ——《梅花易数》物卦起例（后端法）与年月日时起卦

### 一处修正示例：「电脑」为何归乾

初版把「电脑」归离，理由是「离为电」。核查后**判定为错**，已改归乾：

- 《梅花易数》乾属明列「金宝、圆物、刚物」，民间歌诀乾条有「冠镜木果钱钟表」
  「高档用品如轿车，圆物刚物全是了」
- 电脑主机为金石刚硬之实体，与《说卦传》离之象「火、日、电」（主光明外照）不合
- 离之「电」当以**发光显像**之物属之，故「显示器」「屏幕」「手机」归离，**电脑主机归乾**

此类辨析共修正 20 处映射偏差（含伞、音箱、锅等别名），并全部写入 `alt` 字段说明取舍。

### 五音不只是音高：音色维度

《礼记·乐记》所言「清浊」是音色概念，故本作令**五音直接决定音色**：

- 卦 → 乐器（《白虎通》八音配八卦）：八种乐器各有独立物理规格（泛音列、衰减、瞬态、气声）
- 调式 → 音色修饰（《乐记》清浊次第）：以清浊度为轴，经三层调制（频谱倾斜 / 泛音浓度 / 起音余韵）
  作用于每种乐器

音色差异由 `scripts/verify-timbre.js` 以 Goertzel 频带分析量化验证，
八种乐器的「宫 → 羽」高频占比跨度为 6.2 ~ 35.3 个百分点，全部单调递增。

### 伴奏层：中国传统「丝竹」体制，不是简单加背景音乐

主旋律之外的伴奏，每一层都依传统音乐理论立论，各有出处（详见 `core/classics.js` 的 `ACCOMPANIMENT`）：

| 层 | 名称 | 依据 | 做法 |
| -- | ---- | ---- | ---- |
| ① | 宫音踏板 | 《礼记·乐记》「宫为君」，君为主、臣民附之 | 宫音贯串全曲不换，确立调式根基 |
| ② | 和声垫 | 《乐记》郑玄注「五声，宫、商、角、徵、羽」 | 只取五声内的三度叠置：徵-羽-宫、羽-宫-角、宫-角-徵；**绝不引入变宫、变徵**，以免半音化而失五声本色 |
| ③ | 支声应和 | 中国器乐「一主一从」之制 | 取主旋律骨架音作同度/低八度应和，非西方对位和声 |
| ④ | 节奏骨架 | 《白虎通·礼乐》引《乐记》「鼓，震音也；柷敔，乾音也」 | 柷敔干硬短促落板定拍，鼓低频冲击落重拍 |
| ⑤ | 散板 | 《乐记》散节奏不立小节 | 密度随卦德与段落变化，不套用西方固定拍号 |

关键约束：伴奏和声**严格限于该卦调式的五个音级**，三音组内无半音相邻。
由 `scripts/verify-loop.js` 对 64 卦逐一校验（576 项音阶归属 + 半音冲突检查）。

踏板与和声垫合并为同一个多音 pad 音符一次渲染，
既避免两套低音互相干扰，也把渲染采样量压到原来的三分之一。

### 循环播放（小程序端）

小程序端播放器支持单曲循环（同一卦的心音反复播放）：

- 首页播放器「🔁 循环」按钮，开启时以朱色标示，状态存于全局播放引擎，跨页保持
- 实现要点：循环重播时**复用已渲染的 PCM**，不重复渲染（60 秒音频可省下约 1 秒）

网页 / APP 端则改为**即兴连播**（见下节），不再有固定循环按钮与进度条。

### 即兴连播：每一轮都是新编的这支卦（2026-10）

网页 / APP 端播放器去掉进度条，改为**无限连播的即兴演奏**：

- **卦象身份固定**：调式、律、主音、音色、六爻旋律与节奏骨架不变——听得出始终是同一卦；
- **演奏法每轮随机**：散板引子、装饰疏密、和声轮转、支声模式、低音句读、句尾应和、
  八度升降、终止式和弦、力度弧线九种变体随机组合；
- **种子含时间与随机数**：`Date.now() × 常数 + Math.random() + 轮次`，
  同一毫秒内也不会重样，保证「根据卦的逻辑，结合时间和随机性实时生成」，
  而不是一个卦复用一段音频；
- **叠尾无缝衔接**：下一轮在上一轮结束前 2 秒淡入 1.6 秒，上一轮同步淡出；
  播放中即预渲染下一轮，感知不到断点；
- **小节字幕**：起 / 承 / 转 / 合四段与「即兴第 N 段」实时显示在播放卡片上；
- **导出**：`exportLastWav()` 导出正在听的这一轮，而非缓存的第一轮。

由 `scripts/verify-generative.js` 专项验证（12 组 17 项）：不同种子必得不同编舞、
即兴不改变卦象身份、全部音符仍在本调式五声内、不引入变宫变徵、默认路径保持确定性
（离线测试可复现）等。

### 音层体系：疗愈九频 + 自然音层（2026-10）

在不动五声根本的前提下，提供一组**可选择加入**的氛围音层，全部实现于
**渲染层后期铺底**（混响之后、压缩之前），**不进音符表**——
音符表仍是纯五声，五音校验（`verify-loop` / `verify-generative`）不受影响。

**疗愈音层（索菲吉奥九频）** —— 174 / 285 / 396 / 417 / 528 / 639 / 741 / 852 / 963 Hz，
当代音疗流派所用，每频配一名目与中性介绍（松弛 / 温润 / 安定 / 更新 / 澄明 / 亲和 /
清畅 / 觉醒 / 静观）。按卦取频（`(卦序-1) % 9`），同卦同频，也可在面板改选其他频率；
默认音量仅为主体 5%（实测能量占比约 16%），平方淡入淡出。

**自然音层（合成生成，非录音素材）** —— 雨声、鸟鸣、篝火、风声、溪流五层，可多选叠加：

| 音层 | 合成手法 | 电平 |
| ---- | ---- | ---- |
| 雨声 | 一阶低通白噪成雨体 + 稀疏高通雨点 | 0.12 |
| 鸟鸣 | 带通噪底 + 短促 FM 啾声脉冲 | 0.13 |
| 篝火 | 白噪低通褐鸣 + 窄带爆裂噼啪 | 0.10 |
| 风声 | 褐噪经两个慢 LFO 驱动低通（风的呼吸） | 0.10 |
| 溪流 | 双带通噪 + 中频细密波纹 | 0.11 |

各层按 `√(采样率/44100)` 归一，实测单层能量占比 3~8%、全开合计约 22%（阈值 < 35%），
不喧宾夺主；总音量另有滑条统一控制。确定性伪随机合成，同参数两次渲染逐位一致。

音层面板每个 chip 也配同形状同色的迷你波形图标，未播放时同样缓流可见。

界面明示「当代音疗流派所用，非古律、不涉疗效」，可一键关闭；
关闭时与纯净渲染**逐位一致**（三种边界情况均验证）。

**实时音层总线（浏览器端）** —— 音层不烘进 PCM，改由常驻 Web Audio 节点实时合成：
疗愈频率为双正弦振荡器（基频 + 低八度），自然层为循环白噪经各层专属 BiquadFilter 链。
每层是「基增益 → VCA」两级结构，LFO 只叠加在 VCA 上（基准恒为 1）——
基增益归零时输出必为零，故关闭即真静音、总音量滑杆真正管用。
开关 / 频率 / 音量 **300ms 内可闻**（`scripts/probe-ambient.js` 在真实浏览器量测验证）。
Node 与小程序仍烘进 PCM，保证导出 WAV 与小程序端听感一致。

### 动听化：即兴变体与旋律发展

在五声根本之上，用演奏法、配器细节与**旋律发展手法**提升「动人心弦」的程度
（音仍全部取五声内的音）：

- 散板引子：高音区五声点慢起，先有声后有其形；
- 句尾应和与支声：主旋律句尾以阶梯音应和，如回声；
- 主题后半移高八度 + 泛音点：越奏越亮，尾声有泛音余韵；
- 力度弧线：起 0.90 → 承渐强 → 转 1.06 → 合 0.88，四段有呼吸；
- 即兴轮混响略增（0.30 → 0.32），掩盖轮次接缝、托住空间感；
- **轮内发展**（`opts.form` 开启）：主题的每一遍陈述选用一种传统发展手法 ——
  加花（五声阶级进环绕骨干音）、换头合尾（变头部而尾音不变）、
  隔凡（下五度移宫）、压上（上五度移宫）、分裂重组（动机单元重组），
  故一段之内动机已在发展，不再是原样复读；
- **跨轮宏曲式**（即兴连播已启用）：八轮一循环（呈示·应和·加花·隔凡·分裂·压上·换头·再现），
  再现轮主题回到原调 —— 听得出是这一卦，却已走过一段路程。
  界面在「即兴第 N 段」后标出当前所处阶段（如「隔凡」）。
  发展手法的文献依据见 `core/classics.js` 的 `MELODY_DEV` 登记；
  `scripts/demo-strategies.js` 可渲染三种策略的试听样（现行 / 轮内发展 / 跨轮曲式），
  改主程序之前先试听选定。
- **移宫不伤和声**：隔凡/压上遍里，旋律、宫音踏板、和声垫、支声**同步平移**；
  且踏板与低音**不越过移宫边界**（即止即起），避免旧宫长音与新宫形成半音撞音。
  校验见 `scripts/verify-generative.js` 第 14 组（36 项）。

### 为什么自己写渲染器

微信小程序的 `wx.createWebAudioContext()`（基础库 2.19.0+）**不支持** `createConvolver`（混响）与 `createStereoPanner`（声像），也没有 `OfflineAudioContext`。原有基于 Web Audio 的引擎无法移植。

`render.js` 用纯数学生成 PCM，不依赖任何 Web Audio API：

- **加法合成** —— 钟磬的非谐泛音列 `[1, 2.0, 2.76, 5.4]`
- **减法合成** —— 箫、埙、管（吹管类）的锯齿波经 TPT 状态变量低通滤波（含 polyBLEP 抗混叠）
- **瞬态噪声** —— 鼓与石磬的击打感，经高通滤波
- **清浊倾斜滤波** —— 五音「宫至浊 → 羽最清」的频谱枢轴，对所有有音高的乐器生效
- **恒定功率声像** —— 替代 `StereoPannerNode`
- **Schroeder 混响** —— 4 并联梳状 + 2 串联全通，替代 `ConvolverNode`
- **前馈压缩器 + 峰值归一化 + 软限幅**

八种乐器各有独立物理规格（泛音列、衰减、瞬态、气声量），
见 `core/render.js` 的 `VOICE_SPECS`。

**渲染性能**（44.1kHz 立体声，68 秒音频）：

| 优化项 | 说明 |
| ------ | ---- |
| 正弦查表 | 2048 点表 + 线性插值，替代逐点 `Math.sin` |
| 整数相位累加 | pad 的多路失谐用 16 位整数相位，掩码取表下标，免去浮点归一化 |
| 递推包络 | 逐采样乘固定衰减系数，替代逐点 `Math.exp` |
| 合并 pad | 踏板与和声垫合成一个多音音符，采样量降至约 1/3 |
| 提前退出 | 包络衰减至听不见时终止该音的渲染 |

实测渲染速度 **65× 实时**（68 秒音频约 1.0 秒完成），
故小程序端可实时生成，无需预渲染。

## 五、拍照识象（已实现）

### 设计要点：物象取物本身

梅花易数取的是**物本身**，不是它上面有什么。这一点直接写进了模型提示词：

> 只看物体本身。不要考虑某个物体上面放着什么、里面装着什么。
> 例如"一张空桌子"只输出"桌子"，不要输出"空桌面"。

所以「空椅子」就是椅子（艮），「桌子」和「餐桌」取的是同一个卦（艮为桌案）——细分类目不影响取卦。

### 三条路径，任何一条都不产生死路

| 情况 | 行为 |
|---|---|
| 识别成功 | 出候选卡（物象 + 卦 + 理由 + 置信度），**可点任一项改卦** |
| 识别不到物象 | 按《说卦传》方位取卦，明示"非识别成功"，给搜索框 |
| 未开通云服务 | 直接进手动模式，展示全部 203 个物象 |

手动选物象与拍照识别**取卦结果完全一致**——识别只是省去翻找，不是必经步骤。

### 物象库已扩容：85 → 203 个

原库偏古典（金玉、釜、卜卦之具），用户找不到自己家的东西。新增 6 类现代日常：

| 分类 | 数量 | 例 |
|---|---|---|
| 居家 | 22 | 桌案、椅子、沙发、窗户、钥匙、雨伞 |
| 器用 | 32 | 手机、电脑、空调、冰箱、吹风机、眼镜 |
| 出行 | 19 | 汽车、地铁、红绿灯、行李箱 |
| 饮食 | 23 | 米饭、咖啡、杯子、筷子 |
| 衣物 | 10 | 外套、鞋子、帽子 |
| 数字 | 12 | 手机屏幕、二维码、进度条 |

配套 **420 条别名归一表**（`IMAGE_ALIAS`），覆盖中英文与口语：

```
椅子 / 凳子 / 板凳 / chair / stool  →  椅子（艮）
桌子 / 餐桌 / 书桌 / 餐台 / desk / table  →  桌案（艮）
树 / 花 / 草 / tree / plant / flower  →  草木（巽）
```

### 启用视觉识别

**小程序**（推荐，API Key 不入前端）：

1. 开发者工具 → 云开发 → 建环境
2. 把环境 ID 填入 `miniprogram/app.js` 的 `globalData.envId`
3. 云控制台 → AI+ → 开通，确认模型支持图片（如 `hy-vision-2.0-instruct`）
4. 右键 `miniprogram/cloudfunctions/vision` → 上传并部署：云端安装依赖

**网页版 / APP**：在识象区点「技术选项」填入兼容 OpenAI 协议的视觉接口地址与 Key。留空即用手动模式。

> 架构约束（已核实）：`wx.cloud.extend.AI` 的 `generateText` **不支持上传图片**，所以识别必须经云函数转发。这是硬限制，不是配置问题。

- **学易栏新功能经真实浏览器验证**：易之生成四象图矢量爻形正确（阴阳爻不再混淆）、
  学易默认折叠、按上下卦找卦定位准确（如「上乾下坤 → 天地否」）、古代卜筮方法五章齐备
